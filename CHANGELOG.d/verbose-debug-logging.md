Added a `--verbose`/`--debug` CLI flag (also settable via `CONTEXTUAL_ORCHESTRATOR_VERBOSE=true` and a restart for an already-deployed server, without editing its CLI invocation) that enables stdlib DEBUG-level logging of the route-vs-conduct decision, each route/conduct step's agent and latency, `ModelClient` provider request/retry/backoff attempts, `TaskOrchestrator._invoke`'s failover classification, per-agent circuit-breaker open/half-open/closed transitions, model discovery (folded in from #941's secret-free diagnostics), the streaming route path (`TaskOrchestrator.stream_route`'s agent selection/outcome and `ModelClient._stream_send`'s provider-request boundary — both HTTP surfaces that stream, Chat Completions and Responses, share this one path), and the HTTP request/response lifecycle in `server.py` (timed to cover a full streamed response, not just its first byte; a malformed absolute-form request target or an oversized method token degrades only the debug log line, never the real response). Off by default with no behavior change. Every new log record is bounded and secret-free by construction — never an API key, an `Authorization` header, a raw exception message, or prompt/response content — and DEBUG is enabled only on the specific, individually audited loggers this change and #941 verified safe, never the root logger or a whole-package logger, so an unrelated, unaudited call site elsewhere in the process cannot become newly visible (ADR 0125).
