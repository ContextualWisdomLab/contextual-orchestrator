Fixed `/v1/chat/completions` rejecting `stream=true` with `stream_options.include_usage=true` whenever `tools` were present, even though the tool-loop passthrough already has the complete non-streamed provider response (with its real `usage`) before framing it as SSE. The fail-closed guard now only applies to the multi-step `response_format`-without-`tools` conduct path, whose usage would undercount true workflow cost (only the final synthesizer step is measured). Also removed `_chat_response_sse_chunks`'s text-derived `usage_source: "estimated"` fallback for the case where a provider omits `usage` — it is now silently omitted from the SSE stream, matching the same provider-reported-only honesty boundary already enforced on the other two streaming usage paths (`ModelClient.stream_chat`, `chat_completion_chunks`).
