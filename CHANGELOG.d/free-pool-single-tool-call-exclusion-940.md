Fixed `orchestrator/free` candidate selection ignoring the tool-call capability evidence discovery already records (#940): an agent tagged `tool_call:single` (a provider rejected the discovery probe's multi-tool `parallel_tool_calls: true` request) was still selected for a request with two or more tools or an explicit `parallel_tool_calls: true`, so the passthrough path spent one doomed provider round-trip before failing over. `TaskOrchestrator._is_general_free_agent` now accepts the inbound `chat_body` and withholds such an agent only for that proven-rejected request shape; a single tool without the flag, `parallel_tool_calls: false`, or an agent without evidence stays eligible (positive declarations only, per ADR-0035), and the existing single-tool-call 400 failover remains the safety net. Route, conduct, and streaming text paths are unchanged.
