Closed leaked sqlite3 connections that were surfacing as `ResourceWarning: unclosed database` across the test suite (issue #1168). Root cause: test-owned lifecycle bugs, not a product defect — `_AgentPoolStore` already opens and closes short-lived connections correctly at every one of its five call sites (`try`/`finally`), and `TaskOrchestrator.close()` already releases the durable `_StateStore` connection it owns. The leaks came from tests that (1) used `with sqlite3.connect(...) as connection:` believing the context manager closes the connection, when it only commits/rolls back the open transaction, or (2) opened a bare `connection = sqlite3.connect(...)` with no `close()` at all, or (3) constructed a `TaskOrchestrator(..., state_db=...)` and never called the `close()` it already exposes. Fixed by closing every leaking connection deterministically (`contextlib.closing(...)` for the `with ... as` sites, `try`/`finally` for the bare ones, and `orchestrator.close()` for the state-store-backed orchestrators) in `tests/test_model_timeout_policy.py`, `tests/test_agent_pool_db.py`, `tests/test_metering.py`, `tests/test_structured_output_distinct_fallback.py`, and `tests/test_cost_ledger_boundaries.py`. `tests/test_cost_ledger.py` is intentionally untouched here — it is covered by the separate, not-yet-merged `test/cost-ledger-sqlite-close-1168` branch (PR #1173) and still carries its own unclosed-database warnings on this base commit. No production code changed.
