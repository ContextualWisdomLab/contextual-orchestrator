OpenCode Go discovery now applies the official mixed-protocol endpoint table: only models documented for `/v1/chat/completions` enter the generic CO chat pool; `/responses` and `/messages` models fail closed until protocol-specific adapters exist. This prevents valid Go credentials from being sent to the wrong upstream endpoint.

Added OpenCode Go as a second, subscription-gated provider source (`OPENCODE_GO_API_KEY`, `https://opencode.ai/zen/go/v1/models`), reusing the existing OpenAI-compatible discovery pattern and OpenCode Zen's Models.dev cost/modality join (ADR 0130). Registering only a Zen or only a Go credential discovers exactly that provider's catalog; the two never share a credential name even though both accept the same key format, mirroring the existing NVIDIA NIM primary/sub account-boundary precedent. Also documented Bytez's already-fixed bare-token `Authorization` scheme and the previously undocumented OpenCode Zen row in `docs/kv-credentials.md`'s provider table, and added a code comment explaining why Bytez's `zdr_capable` stays at its conservative default (no published Bytez zero-data-retention policy).
