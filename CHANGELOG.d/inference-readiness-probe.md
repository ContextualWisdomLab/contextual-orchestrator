Added `GET /v1/readiness`, an inference-scoped provider readiness probe (issue #926) so a minimal-privilege caller such as the org's CI review sidecar can get real per-candidate `status`/`failure_code`/`latency_ms` diagnostics without an admin-scoped token. It reuses `provider_readiness_report()` and returns an explicit allowlist of fields — no credentials, base URLs, admin audit fields, or raw error bodies. The existing admin-scoped `/api/v1/provider_readiness/latest` is unchanged.
