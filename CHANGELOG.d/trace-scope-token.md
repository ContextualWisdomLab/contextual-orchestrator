Fixed `SecurityConfig.authorize` letting a bare single `auth_token` satisfy the `trace` scope unconditionally, even in split admin/inference token mode, with no raw-library-path test covering it (issue #117 acceptance item 9). Added an explicit `trace_token` credential: it is the only credential that authorizes `trace` once configured; single-token mode keeps the documented `auth_token` local escape hatch; split admin/inference mode without a `trace_token` now fails closed with `401` as ADR 0026 already documented, and `admin_token`/`inference_token` never satisfy `trace`. Wired `--trace-token`/`--trace-token-key` in the CLI exactly like `--inference-token` (KV credential name `CONTEXTUAL_ORCHESTRATOR_TRACE_TOKEN`, resolved via `get_credential`, no runtime env reads).
