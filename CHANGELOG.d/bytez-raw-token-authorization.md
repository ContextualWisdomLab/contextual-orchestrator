Fixed Bytez model discovery and chat routing sending a malformed `Authorization: Key <token>` header. Bytez's documented API requires the bare credential with no scheme word at all (`Authorization: <token>`, per https://docs.bytez.com/http-reference/list/models.md), so every request was rejected with `401 Unauthorized`, which the provider-catalog bootstrap correctly (but silently) treated as a failed provider and rolled `BYTEZ_API_KEY` back out of the credential KV on every run — the root cause of the scheduled `Provider catalog sync` workflow's persistent `credential inventory mismatch: ['BYTEZ_API_KEY']` failures. Replaced the ad hoc `f"{auth_scheme} {api_key}"` string built at each of the twelve call sites across `orchestrator.py` and `model_discovery.py` with one shared `format_authorization_header()` helper and a new `AUTH_SCHEME_RAW_TOKEN` sentinel for providers with no scheme word.
