Added a `structured_candidate_rejected` DEBUG line for strict structured-output failover. When a candidate's synthesis or repair output is rejected, the gateway now logs `agent_id`, `model`, `stage` (`synthesis`/`repair`) and a bounded `reason` (the existing validation code such as `schema_violation`/`invalid_json`, or `provider_error`/`provider_upstream_error`/`synthesis_exception`; anything else becomes `unclassified`) before recording the circuit failure. Provider content is never read into the line. Previously such candidates showed only `circuit_failure`, so an unusable response could not be told apart from a transport failure (.github Noema run 36166447802).
