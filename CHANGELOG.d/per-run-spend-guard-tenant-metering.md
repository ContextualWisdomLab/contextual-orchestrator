Added a per-run spend guard, provider-limit drop, and tenant metering (ADR 0138). Every provider chat call — including `route_once`, streaming, and sampled baselines — is checked before send against an optional in-memory per-run USD cap (`--run-max-cost-usd`, default: no cap) plus optional LiteLLM-style virtual-key and tenant budgets (`max_budget`, `soft_budget`, `budget_duration`; the tightest limit wins). Paid admission uses a configured total-token ceiling priced at the costlier prompt/completion rate, reserves that upper bound atomically across concurrent run branches, and fails closed when price or total-token authority is unavailable. Unknown outcomes consume the reservation for budget safety while retaining unknown charged cost. The former `0.5` baseline threshold is removed; paid baselines under a hard cap require explicit allocation authority, while zero-cost or uncapped baselines can run. A provider spend-limit error (OpenRouter 402 `limit_source`, OpenAI 429 spend-limit codes, OpenCode Zen 401 `CreditsError`/`MonthlyLimitError`/`UserLimitError`, OpenCode Go 429 `GoUsageLimitError`, Bytez 402, Experiential 429 `insufficient_quota`, including mid-stream errors in an HTTP 200 stream) drops only that provider for the rest of the run; the run fails closed when none remain. Each provider call is metered as a tenant-attributed `UsageRecord` into an in-memory or append-only JSONL store (`--spend-ledger-path`), and the CLI can write a per-run usage summary artifact (`--run-usage-summary`).
