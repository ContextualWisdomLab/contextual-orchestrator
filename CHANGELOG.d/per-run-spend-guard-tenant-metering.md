Added a per-run spend guard, provider-limit drop, and tenant metering (ADR 0138). Every provider chat call — including `route_once`, streaming, and sampled baselines — is checked before send against an optional in-memory per-run USD cap (`--run-max-cost-usd`, default: no cap) plus optional LiteLLM-style virtual-key and tenant budgets (`max_budget`, `soft_budget`, `budget_duration`; the tightest limit wins). Paid admission reserves a cost upper bound before send: exact prompt tokens × prompt price + the sent `max_output_tokens` × completion price when both are known, otherwise the configured total-token ceiling (`context_window`) priced at the costlier prompt/completion rate. In-memory transactions cover concurrent run scopes; JSONL persists reservation/release events under a POSIX file lock so separate processes cannot spend the same headroom. Missing file-lock authority refuses shared hard budgets without disabling uncapped metering. Unknown outcomes, unknown historical costs, and crashes fail closed for the affected hard-budget scope while preserving unknown charged cost; with `budget_duration` they stop counting at the next window boundary, and an operator can settle a reservation with an explicit cost, reason and operator via `python -m contextual_orchestrator spend-settle` (`spend-reservations` lists them), which is the release path for all-time budgets. `measurement_unavailable` refusals name the original provider error (class, HTTP status, and in-run message/cause). Price/limit currency mismatch also fails closed without invented exchange rates. Ledger path I/O errors use the CLI argument-error surface, and recursive untrusted provider JSON cannot abort classification. Under a hard cap a paid sampled baseline runs only while at least `--baseline-min-remaining-ratio` (default `0.5`) of every applicable cap would remain after its upper-bound cost; otherwise it is skipped with reason `baseline_headroom_exhausted` in both the comparison report and the run refusals. Zero-cost or uncapped baselines always run. A priced route with neither request token bounds nor a positive `context_window` is refused as `missing_context_window`, while free and zero-cost routes keep running. A provider spend-limit error (OpenRouter 402 `limit_source`, OpenAI 429 spend-limit codes, OpenCode Zen 401 `CreditsError`/`MonthlyLimitError`/`UserLimitError`, OpenCode Go 429 `GoUsageLimitError`, Bytez 402, Experiential 429 `insufficient_quota`, including mid-stream errors in an HTTP 200 stream) drops only that provider for the rest of the run; the run fails closed when none remain. Each provider call is metered as a tenant-attributed `UsageRecord` into an in-memory or append-only JSONL store (`--spend-ledger-path`), and the CLI can write a per-run usage summary artifact (`--run-usage-summary`).
