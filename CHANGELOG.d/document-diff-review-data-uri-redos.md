Fixed CodeQL `py/polynomial-redos` in `document_diff_review`: the inline data-URI leak check `_DATA_URI` used an unbounded `data:[^,\s]*,`, which `search()` rescans to the end of the text from every `data:` occurrence (quadratic on `"data:" * n` without a comma). The header before the comma is now bounded to 256 characters (`data:[^,\s]{0,256},`), so the scan is linear; data URIs with a header of at most 256 characters are still rejected as `inline_binary_content`.
