Added a counting-provenance registry (`contextual_orchestrator/token_counting.py`) that binds exact chat-message token counting to a citable official source and its exact declared model scope, per issue #1157. `COUNTING_PROVENANCE_REGISTRY` records, per exact model identifier, the `tokenizer`, `framing_source` (currently the OpenAI Cookbook's "How to count tokens with tiktoken", fetched live 2026-09-14, scoped to exactly the seven dated model identifiers it names), `supported_fields` (`role`/`content`/`name`, string-valued only), and `unsupported_fields` (tools, tool/function calls, non-text content parts, instructions, prior response/conversation references). `NativeExactTokenCounter.describe_messages`/`count_messages` now return an exact, provenance-bound count only inside that scope; any unsupported field, non-text value, or out-of-scope model keeps raising `TokenCountUnavailable`, naming the offending field. Added `describe_message_count()` as a counter-agnostic convenience returning a `MessageCountResult` with `count_source`. `chat_completion_response()` gained an optional `prompt_count_source` field (populated by `contextual_orchestrator.server._prompt_count_source`) that is present only when the served request's exact prompt-message count was obtained from this registry, and omitted — never fabricated — otherwise. Tool/modality/multi-turn-context token accounting remains open per #1157; this is the smallest honest step, not a full resolution.
